INSTRUCTOR GUIDE / ASSESSMENT RUBRIC

Teaching the workflow without teaching a model zoo.

This guide supports a short university workshop, tutorial session, or self-directed project review. The objective is disciplined evidence, not algorithm coverage.

Intended use

The material is designed for learners with basic Python and pandas experience. A complete pass takes approximately 3–5 hours: 45–60 minutes of guided reading, 90–120 minutes of notebook practice, and 60–90 minutes completing the six project artifacts.

It can be taught as one half-day workshop, three shorter sessions, or a self-paced assignment. It is a compact module rather than a replacement for a full-semester data-science curriculum.

Common misconceptions

  • “More advanced model means stronger project.” The house-price example shows the opposite: the simple baseline wins.
  • “Accuracy is the default target.” Ask what error costs and select a metric that reflects the action.
  • “Preprocessing is separate from modelling.” Transformations must be fitted inside the training boundary.
  • “A notebook that runs is deployable.” Delivery requires documented inputs, ownership, monitoring and review triggers.
  • “A good chart proves the conclusion.” A chart explains evidence; it does not replace the research protocol.

Evidence note

The project has automated evidence that the code, links and responsive layouts work. It has not yet been validated through a controlled study of learner outcomes. A useful next test is to ask 3–5 target learners to complete one case without assistance and observe where they become blocked.

Review questions

  1. Can the learner state what decision the model changes?
  2. Can the learner identify a field that would leak the future?
  3. Can the learner explain why a baseline is necessary?
  4. Does the evaluation recommend an action rather than just report a score?
  5. Could a second analyst rebuild the result from the repository?
