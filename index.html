课程范围

这是通用 Data Science Tutorial。三个案例使用固定随机种子的合成数据， 用于学习流程和评估方法，不构成真实市场、信贷、价格或经营结论。

01 BUSINESS UNDERSTANDING

先把“做一个模型”改写成“支持一个决定”。

数据科学的第一个错误通常不是模型选错，而是问题定义得太模糊。 你需要知道：结果由谁使用、什么时候使用、会触发什么行动。

Learning objectives

  • 把业务想法转换成可检验的数据问题。
  • 明确目标变量、使用场景、评估指标和错误成本。
  • 写出一份不包含算法名的研究问题说明。

一张最小问题画布

Business Understanding 不是写公司介绍。它是一份“决策合同”： 说明模型输出如何变成行动，以及什么结果才算有帮助。

Problem statement template

For [decision owner], estimate [target] at [decision time] so that [action] can be prioritised. Prefer a model only if it improves [decision metric] over [baseline], subject to [constraints].

三个案例的决策定义
案例 决策 目标 主要指标 错误成本
客户流失 选择哪些客户进入挽留名单 未来是否流失 Recall、Precision、挽留成本 漏掉高风险客户；打扰低风险客户
房价预测 预算估计或初步筛选 成交价格区间 MAE、RMSE 高估导致亏损；低估错过机会

Python · write the brief before modelling
research_brief = {
    "decision": "Which customers should receive a retention offer?",
    "target": "churned within the next 30 days",
    "decision_time": "month-end, before the campaign starts",
    "baseline": "contact everyone, or target only by tenure",
    "metric": "recall at an acceptable contact volume",
    "constraint": "retention budget covers 20% of customers",
    "failure_cost": "missed churn vs unnecessary discount",
}
Checkpoint · 这个目标是否足够可执行？

“预测客户行为，提高客户满意度”不够具体。更好的版本是： “在每月挽留活动开始前，估计客户未来 30 天流失概率，按挽留预算排序， 并把 Recall 作为首要指标。”后者明确了时点、行动和约束。

02 DATA UNDERSTANDING

先理解数据如何产生，再讨论它能回答什么。

数据理解不是立刻清洗。先建立数据字典，检查覆盖范围、时间口径、 缺失和异常，并确认目标变量是否真的对应业务事件。

Learning objectives

  • 为每一列说明业务含义、类型、生成时间和可能误差。
  • 识别样本范围、目标泄漏、重复记录和分布极端值。
  • 用描述性统计判断数据是否值得继续。

行与覆盖

样本是谁？覆盖哪个时间段？缺失了哪些群体或时期？

字段与口径

单位是什么？是月末快照还是期间合计？是否包含未来信息？

目标与时间

目标变量何时可用？模型的输入信息在决策时是否已经存在？

质量与分布

缺失、重复、异常、类别比例和长期趋势是否合理？

Checkpoint · 为什么先看目标分布？

类别严重不平衡时，Accuracy 可能很高但少数类几乎没有被识别。 目标分布会直接影响基线、评估指标和阈值选择。

03 DATA PREPARATION

数据准备的目标不是“洗到干净”，而是让评估可信。

编码、填补和缩放都需要被看成模型流程的一部分。 它们应该在训练数据上学习，再应用到验证或测试数据。

Learning objectives

  • 在预处理之前先切分数据。
  • 使用 Pipeline 防止预处理泄漏。
  • 根据任务类型选择正确的验证方式。
Training Learn parameters
Validation Choose and tune
Test Use once

三种任务，三种切分逻辑

  • 分类 / 回归：随机切分，并检查目标分布。
  • 分层分类：保持训练和测试中的类别比例。
  • 时间序列：按时间先后切分，未来的数据不能进入过去。

Rule of thumb

缺失值填补、标准化和编码都应写在 Pipeline 内。 先在全部数据上拟合，再切分，是一个隐蔽但常见的泄漏。

Python · preprocessing inside a pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

preprocess = ColumnTransformer([
    ("numeric", Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("scale", StandardScaler()),
    ]), numeric_columns),
    ("categorical", Pipeline([
        ("impute", SimpleImputer(strategy="most_frequent")),
        ("encode", OneHotEncoder(handle_unknown="ignore")),
    ]), categorical_columns),
])
本节原则

切分先于清洗；所有从数据中“学习”的参数，只能在训练集上学习。

Checkpoint · 时间序列为什么不能随机切分？

随机切分会让模型在训练时看到“未来”又被要求预测“过去”， 这会产生现实中无法获得的高分。正确做法是保持时间顺序， 用过去训练、未来测试。

04 MODELING

基线不是形式，它是判断复杂模型是否值得的尺子。

先用最简单、最容易解释的方法建立下限。只有当复杂方法在统一协议下 稳定改善关键指标，复杂度才有理由。

Learning objectives

  • 为分类、回归和时序任务建立合理基线。
  • 在相同切分和相同指标下比较模型。
  • 把参数、随机种子和预测结果保存下来。
Classification

Logistic Regression

先看线性边界能否解释结果，再决定是否引入树模型。

Regression

Linear Regression

透明、稳定，适合作为连续目标的第一把尺子。

Time series

Seasonal Naive

用去年同月预测今年同月。它常常比复杂方法更难打败。

Checkpoint · 复杂模型一定更好吗？

不一定。本教程的房价案例中，随机森林的 MAE 和 RMSE 都高于线性回归； 在三个案例的课程代码中，这一“失败”会保留下来，用于解释基线、噪声和模型容量。

05 EVALUATION

先问“错了会怎样”，再问“模型分数多少”。

评估不是给模型排名，而是判断它能否支持当前决策。 同一条预测，在不同成本和约束下可能需要不同阈值。

Learning objectives

  • 根据任务类型选择指标，不用一个指标评价所有问题。
  • 识别过拟合、分布变化和阈值风险。
  • 把模型指标翻译成业务收益或损失。
MAE

平均绝对误差

预测偏差的绝对平均值，单位和目标变量一致，容易向非技术读者解释。

RMSE

均方根误差

对大误差惩罚更强。适合特别不能接受极端错误的场景。

P / R

Precision / Recall

前者关注命中率，后者关注是否漏掉重要正例。阈值会改变两者。

If the cost of a missed churner is very high
Prioritise Recall
If every false alert is expensive
Prioritise Precision
If large price errors are unacceptable
Track RMSE as well as MAE
If the process changes across time
Test on later periods
评估的三个问题
  1. 结果是否在未见过的数据上保持？
  2. 不同群体、时期或阈值下是否稳定？
  3. 错误是否集中在会改变实际决策的样本上？
Checkpoint · Accuracy 95% 一定是好模型吗？

不一定。如果只有 5% 的样本属于正类，一个永远预测“负类”的模型也能达到 95%。 需要同时查看类别分布、混淆矩阵和与决策相关的指标。

06 DEPLOYMENT & COMMUNICATION

Deployment 不只是上线模型，也包括让结果可被使用。

在教程环境中，交付一个可以重跑的项目、一个清晰的结果说明， 同样属于 deployment。对很多分析项目，这比搭一个复杂 API 更有价值。

Learning objectives

  • 写清运行方式、依赖、数据边界和结果来源。
  • 区分教学案例、离线分析、生产系统三种交付。
  • 识别数据漂移、模型退化和需要重新评估的信号。
01

Reproduce

从原始输入到最终图表，有明确命令和固定环境。

02

Explain

用一页摘要说明问题、方法、结果、限制和建议。

03

Monitor

监控输入分布、关键指标和业务结果，而非只看模型文件。

Checkpoint · 什么情况需要重新评估模型？

产品、客户结构、业务流程或数据来源发生变化时；关键特征的分布明显偏离训练期时； 错误成本改变时；预测结果连续偏离实际结果时。

REVIEW PROJECT CHECKLIST

下一次做项目时，按这张表反向检查。

CRISP-DM 的循环意味着检查不是最后一步。任何阶段发现问题， 都应该回到上游更新问题、数据或评估协议。

Business

  • 决策人和行动是否明确？
  • 指标是否对应用户成本？
  • 基准是否已经定义？

Data

  • 目标在决策时是否可用？
  • 样本范围和时间口径是否清楚？
  • 缺失、重复和异常是否记录？

Model

  • 是否先完成基线？
  • 预处理是否只在训练集拟合？
  • 参数和随机种子是否保存？

Evaluation

  • 测试集是否只用于最终评估？
  • 是否检查子组和时段稳定性？
  • 模型指标是否转为决策含义？

Delivery

  • 新环境能否一键重跑？
  • 图表是否有来源和限制？
  • 是否有明确的下一步建议？

THE TAKEAWAY

流程决定结果是否可信，模型只是流程中的一部分。

CRISP-DM 提供的不是一个需要背诵的六个步骤，而是一种防止自己过早进入建模、 忘记业务目标或误用测试数据的检查机制。
